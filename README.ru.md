# Claude Code Status Limits

Скрипт статус-бара для [Claude Code](https://claude.ai/code), который в реальном времени отображает заполненность контекстного окна и потребление rate-limit квот.

## Что отображается

### Бар контекста

Показывает, насколько заполнено текущее окно контекста разговора. Claude Code резервирует фиксированный буфер автосжатия в 33k токенов и автоматически сжимает историю, когда порог достигнут. Процент буфера зависит от размера контекстного окна: ~16.5% для 200k, ~3.3% для 1M.

Полоса масштабируется до используемой части окна, поэтому она достигает 100% точно тогда, когда autocompact вот-вот сработает.

Её ширина зависит от размера окна — один символ на каждые 50k токенов, но не меньше шести. Окно в 1M получает 20 символов, 500k — 10, а всё, что до 300k включительно, — минимум в шесть символов. Смысл в том, что одно и то же число токенов всегда занимает одинаковую ширину, независимо от того, какая модель используется.

Цвет заполнения меняется в три ступени:

**Серый** — обычное состояние.

**Янтарный** — контекст превысил 150k токенов (эту границу сам Claude Code выделяет, когда сообщает о потреблении) либо уже вошёл в буфер автосжатия.

**Красный** — контекст превысил 300k токенов. На большом окне autocompact срабатывает настолько поздно, что контекст может незаметно разрастись далеко за разумные пределы.

Пустая часть бара подсвечена по зонам — нейтральная ниже 150k, слегка тёплая между 150k и 300k, слегка красная выше — так что расстояние до следующего порога видно ещё до того, как он будет пройден.

### Бары rate-limit

Каждый бар отражает потребление квоты в рамках фиксированного временного окна — 5 часов или 7 дней. Название квоты и текущий процент отображаются текстом прямо внутри бара.

#### Как читать цвета

Каждый rate-limit бар одновременно кодирует два показателя: сколько квоты уже потрачено и как далеко продвинулось время внутри окна. Цвет показывает, что опережает — потребление или время:

**Яркий зелёный** — потребление и время идут вровень, всё в норме.

**Тёмно-зелёный** — время уходит быстрее, чем тратится квота. Вы расходуете лимит экономно и запас ещё есть.

**Янтарный** — квота тратится быстрее, чем проходит время. При таком темпе вы, вероятно, упрётесь в ограничение до сброса окна.

**Тёмно-серый** — данных ещё нет, или окно только что открылось.

#### Оставшееся время

Янтарный бар говорит о том, что квота расходуется быстро, но не о том, сколько времени у неё в запасе. Поэтому в его подписи указано время до сброса окна: `7d (2d left)`. Оно записано одной ведущей единицей — `45m`, `2h`, `3d` — чтобы помещаться даже в узком сегменте.

### Значки сессии

Строка значков после баров описывает саму сессию:

- **Модель** — отображаемое имя, с ⚡, если включён быстрый режим.
- **Контекстное окно** — его размер числом, `200k` или `1m`.
- **Effort** — краткая метка уровня усилий на размышление: `L`, `M`, `H`, `xH` и `Mx` — для low, medium, high, xhigh и max.

Модель и effort используют одну общую четырёхступенчатую цветовую шкалу — сланцевый, зелёный, янтарный, красный, — поэтому одинаковый уровень интенсивности выглядит одинаково на обоих значках. Зелёный, янтарный и красный — те же оттенки, что у баров. Значок размера окна остаётся нейтральным, тёмно-серым, как пустой участок бара: это число, а не категория.

Каждый из трёх значков также сравнивается с настройками по умолчанию. Если значение отличается, значок отмечается в ячейках отступа, а после строки добавляется красный бейдж **DEF**. Обычная причина — возобновлённая сессия: она хранит модель, записанную в сохранённой истории сессии, и игнорирует последующую смену модели по умолчанию.

- **Модель** сравнивается с точностью до версии: Opus 4.5 при умолчании Opus 5.5 считается отличием. Эталон — поле `model` в `~/.claude/settings.json`, затем переменная `ANTHROPIC_DEFAULT_MODEL`. Если модель выбрана как «Default» и поле не записано, эталон берётся из кеша каталога моделей Claude Code (`~/.claude/cache/model-catalog`). Алиас вроде `opus` разрешается в текущую версию семейства по тому же каталогу. Формат каталога внутренний и может измениться; без него проверка модели пропускается.
- **Контекстное окно** проверяется, только если в поле `model` явно указан размер, например `claude-opus-5-5[1m]`.
- **Effort** сравнивается с `modelSettings.<модель>.effortLevel` — туда его записывает `/effort` — а при отсутствии записи с верхнеуровневым `effortLevel`.

Красный бейдж **API** означает, что последнее обновление usage API завершилось неудачей и бары по отдельным моделям отсутствуют. Без этого значка сбой синхронизации неотличим от простого отсутствия дополнительных квот.

### Папка проекта

В самом конце добавляется имя директории проекта, чтобы несколько открытых окон можно было различить с первого взгляда. Оно берётся из директории, в которой был запущен Claude Code, поэтому остаётся неизменным на протяжении жизни окна, даже если сессия переходит в поддиректорию.

## Источники данных

Скрипт получает данные из двух независимых источников.

**Сам Claude Code** передаёт заполненность контекста и состояние 5h/7d лимитов после каждого хода. Эти значения появляются только после начала разговора, поэтому самый первый рендер нового чата использует закешированные данные из предыдущей сессии.

**Usage API claude.ai** предоставляет квоты по отдельным моделям, такие как Sonnet 7d и Opus 7d, включая лимиты, привязанные к одной конкретной модели — например, недельный лимит Fable. Запросы выполняются с использованием того же OAuth-токена, которым сам Claude Code пользуется для аутентификации, поэтому отдельных учётных данных не требуется. API обновляется не чаще одного раза в 5 минут, либо раз в минуту после неудачной попытки, поскольку такие сбои обычно временные.

## Кеширование

Последнее известное состояние каждого бара сохраняется в `~/.claude/status_limits_cache.json`. Благодаря этому бары всегда показывают что-то осмысленное даже в начале нового чата, до прихода первых данных. По мере поступления новых данных — от Claude Code или от API — кеш обновляется; при пересечении источников приоритет отдаётся живым данным от Claude Code.

Все открытые окна Claude Code используют один и тот же файл, поэтому скрипт берёт блокировку на каждый цикл чтения-изменения-записи и заменяет файл атомарно.

## Установка

Добавьте в `~/.claude/settings.json`:

```json
"statusLine": {
  "type": "command",
  "command": "python /path/to/claude-code-status-limits/status_limits.py"
}
```

Укажите путь к директории, куда клонирован репозиторий. Требуются Python 3.10+ и `curl`.

### Ширина полоски баров

Claude Code размещает справа от вывода скрипта другие элементы (например, счётчик токенов), поэтому бары никогда не занимают всю ширину консоли. По умолчанию скрипт рендерится в 120 колонок. Чтобы задать желаемую ширину полоски, передайте её аргументом:

```json
"command": "python /path/to/claude-code-status-limits/status_limits.py 100"
```

Подберите значение так, чтобы бары заняли доступное пространство в вашем терминале.

Ширина охватывает бары и строку значков. Имя папки намеренно в неё не включено и записывается за пределами края, где Claude Code обрезает его по реальной ширине терминала, — поэтому длинное имя проекта никогда не отнимает место у баров.
